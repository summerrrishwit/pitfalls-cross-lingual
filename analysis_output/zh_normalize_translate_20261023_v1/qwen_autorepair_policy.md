# Qwen自主故障修复策略

生效：2026-10-24，用户明确要求卡住或报错时自行诊断、修复并续跑。operations_policy.json v5覆盖旧说明中“所有403均只能等待用户”的调度限制；冻结生产runtime、输入、提示词、schema、审核规则和历史数据保持不变。

- 正常或有请求活动：继续运行，不重复启动。确认卡住或异常退出：按现有进程身份、锁、停滞确认和恢复预算处理。
- 原因不明的403：生产先保留现场退出；冷却30分钟后允许同模型同路由合成验证。单请求及8并发必须全部通过身份、usage和4案例检查，才由守护调用单独授权的自动访问恢复路径，归档后启动一个worker。401/404、身份异常、明确无效密钥/模型权限/配额/账户限制、来源或工具哈希漂移仍不能自动绕过。
- 验证仍403或其他临时故障：不启动worker，保留失败并进入冷却，不因未知403永久锁死恢复分支。仍遵守每滚动24小时最多3次自动尝试及30/60分钟冷却；明确权限或身份故障会报告。
- 遇运维代码问题：定时任务中的代理应进一步定位并在授权范围内自主修复、测试、保存版本和哈希，不能只看到manual状态就结束；不得擅自改密钥、端点、模型或冻结内容。
- 真实生产增长才算恢复成功。健康进程不主动重启；失败、拒绝和待补证不删除，不重新生成到审核接受。Luna/Sol审核仍由独立审核任务负责。
