# V5：预先固定的局部恢复与成对修复

执行前声明；全部推理和测试在已授权远端进行。旧 v3/v4 文件不改写。Validation/Sealed 继续未开启。

1. 使用已缓存的相同模型、相同渲染、相同最后 prompt token 的 resid_pre。诊断层固定为 zero-based 12/20/28/32。
2. 固定诊断面板：所有 25 个定向阳性 variants，加所有 ZH 三臂本来均正确的抗扰动 variants。每个做 Neutral→Targeted 和 Targeted→Neutral 的单层状态替换；只作用于 prefill 的最后 prompt token，后续缓存 token 不干预。另对每层一个按 SHA 选定的阳性 Targeted 做自身替换，必须精确复现基线。
3. 诊断恢复至少一个实际生成阳性后，按事实等权恢复增益、完整答案 margin 增益、较低层次序固定一个层。该诊断允许同事实参考，只能说明局部恢复可能，不能作为泛化修复证据，也不能宣称唯一因果机制。若无恢复，停止后续向量候选，不开启 holdout。
4. 两类方向：ZH 同事实 Neutral−Targeted（variant 先在事实内平均，再平均所有训练事实）；centered ICL（原有双语 ICL−同事实双语零样本召回）。每折仅使用其他 72 facts，来源与 donor 沿用原隔离；不只挑行为阳性。两类方向各取 ρ=.01/.03，向量范数为训练来源 Neutral 状态范数中位数的 ρ 倍。合计四候选，均为 prefill-only。
5. 每候选执行全部 480 个中文 Development 输入及四折×13 个无关控制（532 调用）。沿用既定事实单位、缺失处理、完整答案生成主终点、完整序列 margin 辅助终点与原保留条件。语义复核盲于配置和条件；相同事实/语言/全文结果可复用已有绑定 SHA 的判定。主要 gate 不因新实验而放宽。
6. 局部有信号后，固定一个 prefill 候选做 every-token 和反方向的诊断面板对照；按 Development 实际生成增益、较小 ρ、paired 优先排序。这两类对照不进入合格候选池，不用于事后增加规则。
7. 如果有生成合格候选，则执行其五个范数匹配随机方向的全 532 输入比较。对选定候选另做 18/36/72 来源事实的学习曲线；18/36 各两个预定 SHA 种子的关系分层嵌套子集，仅执行同一固定诊断面板，72 复用正式评估。小来源曲线不作参数选择或 G2 证据。
8. 只有通过完整 G2 后才汇总全 96 Development 来源、固定新 hook 与方向规则、代码和评分判定 SHA，然后依次 Validation、条件通过后 Sealed。旧 every-token 独立执行器不可直接用于 v5；新执行器必须在冻结前验证 hook 一致性。
9. 若四候选均已明确违反保留条件，停止无法改变门槛的额外语义复核，保留缺失；不启动最终来源、Validation 或 Sealed。不无限追加层/强度、不为扩大分母而补旧面板。

未裁决/语义缺失不会强行填值。所有修订判定保留旧记录、原因和文本 SHA；现有 proxy 判断不是 human gold。没有新增事实采集、模型权重训练或数据生成 API 调用。

## V5b 预检修正（尚无跨条件诊断输出）

绝对自身替换的生成一致，但完整序列 margin 不等价。实测缓存/返回状态与真实层输入逐元素一致；teacher-forced 与 prompt-only 层输入存在约 1.9%–2.6% 的相对 L2 差异，绝对替换会引入额外偏移。保留 v5 失败审计；v5b 新目录改用 source−target 的 float32 常量增量，生成与完整序列评分使用同一干预算子。prefill 的自身增量严格为零，必须同时复现生成和评分。该变化在任何 Neutral→Targeted/反向结果前固定，其他层/来源/门槛不变。
