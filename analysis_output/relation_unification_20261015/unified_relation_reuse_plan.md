# 关系统一与历史双模型数据复用方案

审计日期：2026-10-15。状态：离线盘点与设计完成；未进行新模型抽取、语义审核、翻译或行为实验。原始数据及既有冻结产物未修改。

## 结论

建议采用“统一事实注册表 + 分层关系体系 + 定向补审/重提取”，不建议全部重抽。

历史 2,450 条 canonical 记录具有原始来源、两模型标注和选择决定，可以作为待统一的事实候选。旧标签不能自动升级为新的事实审核或正式 PNT 资格。当前未进入 4,513 条关系范围的 3,150 条也应保留；它们被排除的直接原因是分组状态，而不是这一关证明事实错误。

关系统一的目标是提高语义一致性、补充合格事实和形成可用的 donor 池；不能为了凑数把不同任务硬并为一个关系。

历史排除项为 10,561 条双方未提取或无效、609 条单模型抽取被拒绝、5 条答案冲突被拒绝。不能把这些统称为“技术失败”。两份历史原始模型账本分别只有 2 条、1 条记录带本地 validation_errors；这也是不能默认全量重抽的依据。先按排除原因识别技术问题、可修复歧义、非原子事实/推理题，再决定重试。

在 1,986 条答案共识记录中，1,841 条存在至少一个字段冲突，1,033 条 relation_raw 不同，629 条 subject 不同。字段冲突包括正常同义改写，不等于错误率；它说明答案共识不能代替“主体—关系—答案”整体等价审核。

旧 2,450 条有 2,133 种关系签名，2,040 种仅出现一次。按原始关系字符串和类型原文直接分组，压缩效果有限；应先统一表达和类型，再进行关系审核。

### 去重检查的边界

本次以 NFKC、大小写折叠、空白归一检查：两批来源问句的精确交集为 0；历史保留事实与公开源 9,059 条有效抽取的 S-R-A 唯一键交集为 1。历史 2,450 行内部仅有 2,446 个这样的唯一键。这已经说明行数不能直接相加成独立事实数。

上述检查不是语义去重。问句不同可以问同一事实，关系名称不同可以表达同一关系。统一后仍需跨来源的事实等价、实体别名和 leakage component 闭包。

### 当前文件完整性限制

公开源原始抽取账本、事实修订账本与 lineage、五语最终记录在本地；但当前 checkout 缺少 provisional 根目录的实体记录文件，以及 accepted/zh accepted 投影的完整 `full_base_facts.jsonl` 等实体文件，部分阶段仅有 manifest、排除清单和哈希。

因此本报告没有声称已重建全部 7,663 条、已给出全部 3,150 条的语义分类，或已形成合并后的最终基准。实际统一前，优先从原运行位置恢复与 manifest 对应的文件并校验 SHA。若必须重建，要重放确定性过程及已审核的修订，验证输出哈希；不得拿原始抽取覆盖后续修订。文件缺失本身不是要求再次调用模型抽取的理由。

## 二、正式 PNT 应满足什么关系要求

以本仓库 `tasks/task_160_mcq_pnt_protocol.md` 为直接约束：

- relation-conditioned PNT 要求逐项审核并冻结 `probe_relation_id`；普通行为数据不应全部以 broad mapped_relation 作为准入门槛（约 792–804 行）。
- 当前 5-shot donor 必须同关系、不同 leakage component，且不来自该次 evaluation fold（约 638–649 行）。
- 当前 Development 采用四折，每个关系每折 6 条；这是既定小实验设计，不是普遍的 PNT 样本量标准（约 668–683 行）。
- 关系合格之后仍需要 exact-HF 行为资格、自然基线、固定 tokenizer/渲染/评分、独立评估和干预检查。关系归一不会自动完成这些门槛。

按关系分组的 donor，不等于必然为每种关系各训练一个独立干预向量；现有协议的向量估计还规定跨 source facts 的平均方式。新设计必须明确“关系分层报告”“同关系示例”和“关系专属向量”三者，不能混用。

原 PNT 研究区分事实召回与英语到目标语言答案转换，并提出两类干预。当前五语输入共用英语输出只能直接支持相应的召回/扰动结论；如果要复现答案翻译阶段结论，应另设目标语言输出及显式翻译端点。[PNT 原论文](https://aclanthology.org/2025.emnlp-main.762/)

## 三、推荐的关系体系

保留三层，不把“能粗分组”写成“正式关系已确定”：

1. `relation_raw`：保留两模型原文和出处，不覆盖历史。
2. `relation_family`：检索和报表使用的粗类，如创作者、位置、时间、定义。
3. `relation_leaf_id` / `probe_relation_id`：有方向、domain/range、限定条件和独立审核状态的正式关系。

例如 `written by`、`author of this book` 可以在实际三元组语义一致时归为“书籍 → 作者”。“歌曲 → 演唱者”“电影 → 导演”可以同属宽泛创作领域，却不能仅为了扩大 donor 池而合并为同一 probe relation。

“描述 → 术语”和“术语 → 定义”必须区分方向；“人物 → 出生日期”和“电影 → 上映日期”不能直接因为都含 date 就合并。角色 → 演员需要作品/版本限定，歌曲 → 演唱者需要排除翻唱/多版本歧义。先有合格事实及答案等价组，再决定是否能共享关系模板。

每个叶关系定义：语义定义、domain/range、方向、适用限定条件、正例/反例、可接受答案集合策略、模板与版本、审核记录。旧类型是可纠正的弱标注，不能因为两个模型的类型字符串不同就判为不同关系。

不预先规定必须只有若干类。长尾可以留在通用事实库，待补充数据后再进入独立关系分析。

## 四、怎样降低关系归一成本

### 1. 先对齐、后审核，不对每行从头抽取

程序读取历史 canonical、双模型注释、当前事实与修订、旧分类体系；标准化字符串、实体别名、类型同义词。候选关系检索可用词表和本地 embedding，检索结果只是建议。

以事实语义、关系描述、类型、方向及限定条件构造候选簇，不只使用字符串匹配。旧规则优先产生候选映射；遇到多规则命中、逆向关系、类型冲突、约束缺失时进入例外队列。

### 2. 模型审核分两层

- 关系级：提案模型读取已有 taxonomy 和一组不同来源的代表例，提出同义合并、叶关系定义或新类；独立审核模型判断定义和方向是否成立。
- 事实级：对每个拟进入正式 PNT 的记录验证“这条事实是否符合已审核的关系定义”，重点审查类型、问句、答案唯一性和限定条件。代表例审核不能覆盖未检查的整簇。

通过的旧逐条审核若能证明语义和版本完全一致，可迁移其证据；否则补充轻量归属审核。无需让两个模型重新生成所有三元组。模型角色、版本、提示词、输入哈希、输出和 disagreement 仲裁均需保存。旧规则固定的 confidence 不是校准概率，不能按数值高低免审。

### 3. 只重做发生变化的部分

| 问题 | 动作 |
|---|---|
| 事实/答案正确，只是关系别名不统一 | 修改映射及审核证据，不重新抽取事实 |
| 正确事实在旧 taxonomy 之外 | 建立/扩展叶关系，审核归属 |
| 同义冲突或方向歧义 | 对照原始来源消歧；必要时局部修订 |
| 主体、答案、事实内容错误或原问题无法独立回答 | 只对该条重提取/修订并独立复审 |
| 来源非原子事实、需推理、缺少唯一解释 | 保留排除原因；不为凑数强行提取 |
| 仅关系 metadata 改变且所有实际提示字段不变 | 校验哈希后复用译文；重新验证分组/donor 选择影响 |
| prompt、answer、alias、context 或候选改变 | 对受影响字段重新翻译/审核；刷新下游绑定 |

调用按输入内容和 policy 版本缓存、去重，批处理且记录逐条结果。API 成本应在校准批次后按实际 token、复核率和重试率估算；本次不承诺未经测量的成本降低比例。

## 五、统一数据模型与三种视图

同一事实注册表保存：稳定来源 ID、canonical fact ID 与版本、所有来源/模型注释、选用依据、事实审核、关系审核、答案别名、prompt/译文版本、候选与 context、历史曝光、leakage component、split、模型行为结果引用。

现有 base_fact_id 依赖关系字符串等字段；不要因为归一后字符串变化就覆盖原 ID。使用有版本的旧 ID → 新 canonical ID crosswalk，合并事实时保留全部来源，语义修订时保留事实版本。

输出三个可重建视图：

- 事实库：保留未决关系与明确排除项的账本，用于追踪和后续修复。
- 行为实验库：满足事实、输入、翻译、foil/context 和 split 门槛的记录；不要求所有记录都能进入同关系 PNT。
- PNT 库：在行为库基础上，满足正式关系和实验合同的记录；行为缺陷标签仍属于特定模型，不写回事实真伪。

历史 donor、distractor、Neutral 可以作为素材接入；必须按当前 split/component、别名不重叠、语义、翻译及角色要求重新验证。旧 7,976 个错误选项不能因来自原始题目就当作已验证 foil。

## 六、怎样判断关系数量够不够

统一后每个叶关系输出：来源行数 → 去重事实数 → 关系审核通过数 → 输入完成数 → 各语言/全语言通过数 → 各 split 的独立组件数 → 每折合法 donor 数 → 各 exact-HF 模型的实际缺陷/对照数。

“至少有 5 个 donor”是对每个 source prompt 应检查的可行性条件，不是一个关系至少有 5 条就能完成 PNT。要检查每条记录、每折在排除自身组件和 evaluation fold 后是否仍有五个合格 donor。重复上下文、选项顺序、18 个 MCQ 和 6 个 Natural 均不是新增独立事实。

当前共同集合中的歌曲 → 演唱者 446、角色 → 演员 352，可作为优先细化审核的候选；而 386 条 temporal 必须先拆具体语义。旧 description_named_term 494 不应直接填入当前方向未决的定义分组，entity_location 113 也不应整体并入 location_or_habitat。合并总数不等于可用数。

正式样本量取决于预声明端点、独立组件、预期效应与缺陷率。先用 Development 估计并做功效/精度规划，再固定关系主分析集合；不足的关系可作探索性分析或定向补采。不能在看过验证/封存结果后通过合并关系补救显著性。

## 七、执行顺序与验收

1. **恢复完整输入，冻结盘点 manifest。** 对齐历史全量、当前 8,969/7,663、五语数据以及既有曝光记录；恢复缺失实体文件并验证 SHA。
2. **生成统一 registry 与跨来源去重候选。** 不自动强合语义近似事实；保留旧版本和所有决策。
3. **校准关系体系。** 覆盖当前 unresolved、方向未决、历史 mapped/out_of_taxonomy/ambiguous，以及双模型冲突。按来源/类型分层抽样校准，避免只审核大类或容易样本。
4. **执行关系提案、独立审核及事实归属审核。** 保存通过、待定、拆分、合并和拒绝的完整 ledger，生成定向重提取队列。全量重抽仅在来源/语义系统性失效得到证据支持时考虑。
5. **重算泄漏闭包和曝光约束，建立 successor split。** 已曝光 Development 事实及等价事实不能迁入干净 holdout。旧 split 冲突的连通分量应隔离或列为 development-only；不能静默重分配旧冻结基准。
6. **补建并冻结行为输入。** 确定目标、foil、Neutral/Targeted context、翻译与审核；metadata 未变更对应内容可复用。
7. **导出逐关系可行性报告，冻结实验合同。** 验证 donor、组件和四折/新折分设计；再开展确切模型版本的行为、自然基线与 PNT。

本次请求支持统一数据方案与离线审计。现有 160 条协议仍把扩量实验列为小闭环之后另行设计的阶段；本报告不将本次盘点解释为旧 PNT 已恢复执行。若采用扩量 successor，应把新范围和新合同写清，保持旧结果可复现。

验收重点：来源与记录数可对账；映射方向明确且逐条有证据；语义冲突不被静默吞并；既有译文复用有内容哈希依据；每折 donor 检查通过；历史曝光继承完整；事实/审核/生成/翻译/评分的证据层级互不混淆。
