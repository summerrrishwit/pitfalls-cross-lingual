# 临时故障继续处理与尾部补试

零用量网关错误是网关以错误内容返回请求结果，usage字段为0；它不能证明请求从未到达上游模型，因此所有尝试和曝光继续保留，也不能把它当作数据不合格。具体上游故障原因仅凭客户端日志无法确认。

原worker已有每请求最多3次尝试，但连续16次技术故障会全局熔断。恢复又要求8并发全部成功，造成偶发连接失败也会让全队列停留较久。

用户本次要求已实施为独立版本：

- 临时连接/超时/429/5xx/网关零用量失败只记录当前批次，继续其他来源；连续故障共享退避60/120/300秒，不退出worker。
- 首轮结束后统一补试符合条件的技术失败批次，每批最多一个额外轮次，旧checkpoint及attempt前缀先归档。纯schema/语义问题、已耗尽补试和审核拒绝项不重生成到通过。
- 恢复单请求必须成功，8并发至少6成功且每个成功身份、usage、4个合成案例均合格；其余只容忍明确临时技术失败，不把7/8写成8/8。
- 认证/权限、模型身份、路由或数据/程序哈希异常、未知程序错误仍停止。

原manifest、7250输入、目录、runtime、已有EN/ZH内容和审核均未改写。新生产入口由active_worker_runtime.json独立绑定；原冻结finalize继续负责审核归档。定时任务已原地更新，仍每15分钟，40条Luna分派不变。

45项测试通过。已启动唯一新worker(PID99215)，并观察到真实规范化及翻译增长。恢复复用仍有效的真实诊断记录(单请求1/1，8并发7/8，其余1个APIConnectionError)，失败记录保留。实际最新计数见verification.json；原27个失败批次未删除，等待首轮尾部补试。正式行为和PNT门仍false。
